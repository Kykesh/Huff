## The five core lessons from the source material

### 1. Memory is RAW MATERIAL. Retrieval is the OPERATING LAYER.
Most "AI for business" thinking assumes more memory = smarter AI. That's the trap. The shift: build the retrieval layer first. The right context for the task beats the entire archive. See `01_notes/08_company_brain_architecture.md`.

### 2. Decompose by CONTEXT, not by ROLE.
The intuitive mistake: split work by role (planner/implementer/tester). It creates a telephone game where info degrades at every handoff. The right model: ask what CONTEXT each subtask needs. If two need overlapping info, same agent. Only split when context can be truly isolated. See `01_notes/10_multi_agent_systems.md`.

### 3. The 4 agent paradigms have different jobs.
Single → Subagents → Agent Teams → Dynamic Workflows. Each is the wrong tool for the others' jobs. Single for narrow/deep. Subagents for independent parallel exploration. Agent Teams for coordinated multi-stage. Dynamic Workflows for massive parallel + adversarial verification. Most multi-agent failures come from picking the wrong paradigm.

### 4. The hack stack compounds.
32 Claude Code hacks separately = small wins. Stacked together (CLAUDE.md + plan mode + subagents + worktrees + dynamic workflows + ultracode) = a 10x output multiplier. Most people use 6 of 32 and wonder why they're stuck.

### 5. Faceless YouTube is a math problem, not creativity.
Niche selection (RPM × competition × repeatability) decides 80% of outcomes. The remaining 20% is volume. People making $8K–$372K/mo are running production systems, not making single videos.
